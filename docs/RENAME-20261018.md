# Killcam rename — 2026-10-18

## Identity and migration

KillcamReplay 0.9.14 became Killcam **0.9.15**. The plugin GUID is
`com.maschine.Killcam`, assembly `maschine-Killcam`, and public namespace
`Killcam`. Project, Harmony hold owner, scene object labels and current developer
instructions use the same identity. Playback, recording and Core API behavior
are unchanged.

The existing GitHub repository was renamed to `maschine34675/Killcam`. Repository
ID **1321886160** and history are preserved; visibility remains **private**.
The primary checkout is `D:\SPT41\Development\Killcam`; the linked worktree is
`D:\SPT41\Development\Killcam-log-followup`. The latter retains its historical
branch; a directory rename does not silently merge someone else's work.

Before the first configuration bind, copy the former `.cfg` if and only if the
new one is absent, then reload it. Existing new settings win. Failure disables
this launch before recording or patching; no defaults are written over the old
settings. The old config is deliberately retained for recovery.

The obsolete experimental Killcam 1.0.0 shares the new GUID and would outrank
0.9.15 during BepInEx discovery. It must be replaced, not co-installed. The build
deployment scans both owned DLL names, checks locks before moving, and archives
them outside `plugins`. A leftover Replay GUID also makes the new plugin refuse
to load. Arena treats that legacy identity as incompatible rather than as an
absent camera owner.

Implementation commits: Killcam `12396a6`, UNC deployment correction `63c2766`;
Arena `5d53458`; Redeploy install documentation `71e1513`. Redeploy still requires
its client, shared Core, and server when used independently. No Core or server
runtime changes were made for this rename.
